# BeatPass documentation brief

BeatPass connects listeners and recording artists with music producers. The Help Center serves a nontechnical audience who find tasks through recognizable app labels, consistent visuals, and short, encouraging instructions.

## Main journeys

- Listen & discover: find beats, play music, save favorites, build playlists, connect with people.
- Download & release music: check account eligibility, obtain a license, retrieve files and certificates, understand release rights.
- Produce & get paid: apply for free producer access, upload and license beats, manage one owned producer profile and Pro Page, understand insights and payout readiness.

Keep API & Developers separate. Preserve historical release notes with clear historical context; current instructions belong in Help.

## Writing and visual rules

Start with the outcome and eligibility, use the actual app entry point and labels, give short steps, explain visible completion and recovery, then offer useful next tasks. Avoid internal class names, implementation details, forced slang, promotional guarantees, and unsupported prices or time promises. Financial and legal summaries link the governing policy. Current pricing, checkout totals, account allowances, and payout status take precedence over static examples.

Use real current frontend components with invented demo records. Never use customer records or payment details. Keep screenshot source, public theme configuration, state, route, crop, viewport, and capture date in the capture catalog. Generate reusable static MDX figures from that catalog. Figures follow the documentation's selected light/dark theme and use a mobile image on narrow screens. Prefer useful populated workflows; use an empty state only when explaining that state.

## Authority and release limits

This documentation follows the current reviewed application tree. Editorial release status belongs in ignored audit records, not public pages. Application source is read-only. Authored changes stay inside Documentation, with disposable tooling under /tmp. No commits, publishing, deployment, production databases, credentials, real transactions, or canonical-policy edits. Dependencies install only in an unserved disposable checkout. Rendering runs serially through scripts/docs-runtime.mjs; stop the owned preview before validating Mintlify's shared cache.

Producer access remains free. Paid subscriptions do not let producer accounts acquire new standard catalog licenses. The current purchase service also blocks new exclusive catalog purchases by producer accounts; owner confirmation and disclosure alignment remain open. Preserve own-source downloads and existing valid-license retrieval. Separate source-confirmed behavior, observed live behavior, upcoming behavior, and owner decisions. Do not declare production or legal alignment based solely on code or synthetic previews.

Outstanding owner decisions and verification stay in ignored local audit reports. Do not commit those reports to the public documentation repository. Insights is in scope; disabled desktop Companion downloads are not an announced feature.
