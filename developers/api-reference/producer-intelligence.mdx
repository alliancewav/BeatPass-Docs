The Producer Intelligence API supplies producer progress, achievements, and analytics. It covers <Tooltip tip="Experience Points earned through eligible activity. They determine the producer-account level and the Progress leaderboard.">XP</Tooltip> tracking, achievements, social analytics, collaboration networks, contribution graphs, advanced charting, and real-time metrics.

<Info>
  **Base URL:** `https://open.beatpass.ca/api/v1/producer-intelligence`

  **Authentication:** Legacy public leaderboards and batch growth use optional auth. Producer Dashboard leaderboards and all other endpoints require a valid Bearer token.
</Info>

---

## Rate Limits

Shared and endpoint-specific limits apply. Follow returned rate-limit headers and `Retry-After`; see [Rate Limits](/developers/rate-limits). Prefer batch growth reads and fetch detailed analytics only when needed.

## Dashboard & XP

### Get Dashboard Data

Comprehensive dashboard data for the authenticated producer.

```http
GET /api/v1/producer-intelligence/dashboard
```

### Get XP Sources

Breakdown of XP earned by source (uploads, plays, engagement, etc.).

```http
GET /api/v1/producer-intelligence/xp-sources
```

### Get Producer Level

Current XP level and progress to next level.

```http
GET /api/v1/producer-intelligence/producer-level
```

### Get Progress Data (Combined)

Combined producer-account progress endpoint. It returns `scope`, `level`, `earningRules`, `recentXp`, `achievements`, `cached_at`, `cache_duration_seconds`, `achievementCommunity`, and `achievementProfiles`. Community counts and profile previews can be `null` while unavailable; do not treat that as a count of zero. This endpoint does not replace the full dashboard or return the standalone `xp-sources` response.

```http
GET /api/v1/producer-intelligence/progress-data
```

<Tip>
  Use `progress-data` when your screen needs level and achievement progress. Fetch other analytics only when that screen needs them.
</Tip>

### Recent Achievement Unlockers

Read a recent selection of public producer profiles for an achievement. Producer access is required.

```http
GET /api/v1/producer-intelligence/achievements/{achievementKey}/producers?page=1
```

Use the achievement's returned key, rather than its display name or a numeric database ID. `page` accepts 1–5 and defaults to 1. The response includes `achievementKey`, `generatedAt`, `isStale`, `coverage`, `producers`, and `pagination` with `page`, `perPage`, `hasMore`, and `nextPage`.

Follow `nextPage` only when `hasMore` is true. Coverage describes the available recent selection; it is not a complete list of everyone who has ever unlocked the achievement. Preserve unavailable or stale states instead of presenting them as no unlockers. A temporarily unavailable selection returns `503`.

## Track Growth

### Batch Growth Rates (Recommended)

Get local track trend rates for up to 100 tracks in a single request. **Always prefer this over individual calls.**

The response includes only tracks that are currently trending. Tracks that are not trending are omitted from `growth_rates`.

```http
POST /api/v1/producer-intelligence/tracks/growth-batch
```

<Warning>
  Rate limit: 120 batch requests/minute. Each request can contain up to 100 track IDs.
</Warning>

### Single Track Growth (Legacy)

Get the local trend rate for an individual track.

```http
GET /api/v1/producer-intelligence/track/{trackId}/growth
```

<Note>
  Prefer the batch endpoint for multiple tracks. Track trend rates are based on local BeatPass play activity, not Spotify popularity or payout contribution values.
</Note>

## Producer Dashboard Leaderboards (Authenticated)

Read a producer ranking snapshot for a supported category and period. Use freshness fields to show when the ranking was generated.

```http
GET /api/v1/producer-intelligence/leaderboards
```

### Query Parameters

| Parameter | Required | Values |
| --- | --- | --- |
| `artist_id` | Yes | Artist profile the authenticated user can manage |
| `category` | Yes | `earning_share`, `progress`, `audience_plays`, `releases`, or `collaborations` |
| `period` | Yes | `current` for earning share; `all` for progress; `7d`, `30d`, or `all` for activity categories |

Rate limit: **60 requests/minute**.

### Ranking Definitions

| Category | Definition | Scope |
| --- | --- | --- |
| `earning_share` | Current producer earnings-contribution share | Artist |
| `progress` | Cumulative producer-account XP | Producer account |
| `audience_plays` | Track-play events on public attributed tracks, excluding known artist-team users while retaining anonymous plays | Artist |
| `releases` | Public attributed tracks created in the selected period | Artist |
| `collaborations` | Public attributed tracks credited to at least two artists and created in the selected period | Artist |

The `7d` and `30d` periods use exact `[start, end)` rolling boundaries. `all` has no lower boundary. Equal values use standard competition ranking, so values such as `100, 100, 90` receive ranks `1, 1, 3`.

### Response

The response contains the top 20, the requested producer's entry, and up to one adjacent entry above and below when that producer is outside the top 20.

### Errors

| Status | Meaning |
| --- | --- |
| `401` | Authentication is required |
| `403` | The authenticated user cannot access the requested artist |
| `404` | The requested artist does not exist |
| `422` | A parameter is invalid or the category-period combination is unsupported |
| `500` | Unexpected failure reading a producer leaderboard snapshot |
| `503` | No usable scheduled snapshot is available |

## Upload Rhythm Graphs

### Artist Upload Rhythm

Returns one entry per calendar day with the artist's track-upload count and uploaded-track details. The endpoint requires access to the requested artist.

```http
GET /api/v1/producer-intelligence/artist/{artistId}/contribution-graph
```

The route name is retained for compatibility; the response measures uploads rather than contribution value.

### Platform Upload Rhythm

Returns daily upload counts across BeatPass. The Producer Activity page uses this response as optional X-Ray context, not as a normalized comparison or ranking.

```http
GET /api/v1/producer-intelligence/platform/contribution-graph
```

## Best Practices

<AccordionGroup>
  <Accordion title="Use combined endpoints" icon="layer-group">
    Use `progress-data` for level and achievement progress. It does not include every dashboard metric or the standalone XP-source payload.
  </Accordion>
  <Accordion title="Use batch track trend endpoint" icon="bolt">
    Use `tracks/growth-batch` for up to 100 tracks per request instead of individual `track/{id}/growth` calls. Non-trending tracks are omitted from the response.
  </Accordion>
  <Accordion title="Respect cache TTLs" icon="clock">
    Cache behavior differs between legacy leaderboards, scheduled Producer Dashboard snapshots, and per-account analytics. Use returned timestamps, `isStale`, and cache metadata where available; no single refresh interval applies to all of them.
  </Accordion>
  <Accordion title="Debounce real-time requests" icon="gauge">
    Real-time analytics endpoints are expensive. Debounce requests and use appropriate intervals (30s+).
  </Accordion>
</AccordionGroup>
