## Overview

The Messaging API enables direct and group conversations between BeatPass users. It supports real-time features including typing indicators and read receipts.

<Info>
  **Base URL:** `https://open.beatpass.ca/api/v1/messaging`

  **Authentication:** All messaging endpoints require a valid Bearer token.
</Info>

---

## Conversations

### List Conversations

Retrieve the authenticated user's conversations, with pinned conversations first and recent activity next. Use `folder=inbox` or `folder=archive`, `q` for participant/last-message search, and `offset` with the returned `next_offset`. The default limit is 20 (maximum 100). Participant labels are public usernames, never legal names or email addresses.

```http
GET /api/v1/messaging/conversations
```

<ParamField query="limit" type="integer">
  Number of conversations to return. Default: `20`.
</ParamField>

**Response:**

```json
{
  "success": true,
  "data": [
    {
      "id": 1,
      "type": "direct",
      "participants": [...],
      "last_message": {
        "id": 42,
        "message_text": "Hey, love your beats!",
        "created_at": "2025-01-15T14:30:00Z"
      },
      "unread_count": 2
    }
  ]
}
```

### Start Conversation

Start a new direct or group conversation with an initial message. The sender must follow recipients; direct-message replies require the replying user to follow the other participant. Producer ownership or upload permissions are not prerequisites. Paused conversations reject new messages.

```http
POST /api/v1/messaging/conversations/start
```

#### Direct Message

<ParamField body="user_id" type="integer">
  Recipient user ID for a direct message.
</ParamField>
<ParamField body="message_text" type="string" required>
  Initial message text. Max 2,000 characters.
</ParamField>

#### Group Conversation

<ParamField body="user_ids" type="array">
  Array of user IDs for a group conversation. At least 2 recipients required (3 participants total including the sender).
</ParamField>
<ParamField body="title" type="string">
  Optional group conversation title. Max 255 characters.
</ParamField>
<ParamField body="message_text" type="string" required>
  Initial message text. Max 2,000 characters.
</ParamField>

<Note>
  Provide either `user_id` (direct) or `user_ids` (group), not both. You cannot start a conversation with yourself.
</Note>

**Response (201):**

```json
{
  "success": true,
  "data": {
    "conversation": {
      "id": 5,
      "type": "direct"
    },
    "message": {
      "id": 100,
      "message_text": "Hey, want to collab?",
      "created_at": "2025-01-15T14:30:00Z"
    }
  }
}
```

### Legacy Delete Endpoint

The compatibility endpoint archives the conversation for the authenticated user. It does not erase messages. New clients should use the reversible archive endpoint below.

```http
DELETE /api/v1/messaging/conversations/{conversationId}
```

## Archive, Pin, React, and Report

| Method and path (relative to the base URL) | Body | Behavior |
| --- | --- | --- |
| `POST conversations/{conversationId}/archive` | `archived: boolean` | Archive or restore for the current participant |
| `POST conversations/{conversationId}/pin` | `pinned: boolean` | Pin or unpin for the current participant |
| `PUT messages/{messageId}/reaction` | `emoji: string or null` | Replace the caller's reaction or remove it with null |
| `POST conversations/{conversationId}/report` | `reason`, optional `details` | Submit moderation evidence from recent messages |

Each mutation verifies membership. Reactions accept only the six values exposed by the client picker. Report submissions are rate limited. Archive, read reminders, and pins are personal state; they do not change another participant's inbox.

`GET conversations/{conversationId}/messages` accepts `q` to search text. For stable history pagination, pass `pagination=cursor` and the returned `next_cursor` as `cursor`. The offset contract remains available for older clients. Both send endpoints accept an optional `client_message_id` for retry reconciliation; reuse it for the same send rather than creating a new identity.

See [Moderating messages and reports](/help/messaging/moderation) for administrator workflows. Administrative routes have a separate full-admin authorization check; ordinary messaging membership does not grant access.

## Messages

### Get Messages

Retrieve messages for a specific conversation. Only accessible to conversation participants.

```http
GET /api/v1/messaging/conversations/{conversationId}/messages
```

<ParamField path="conversationId" type="integer" required>
  Conversation ID.
</ParamField>
<ParamField query="limit" type="integer">
  Number of messages. Default: `50`.
</ParamField>
<ParamField query="offset" type="integer">
  Offset for pagination. Default: `0`.
</ParamField>

### Get Messages with Read Receipts

Same as above but includes per-message read receipt data.

```http
GET /api/v1/messaging/conversations/{conversationId}/messages-with-receipts
```

---

### Send Message

Send a message to an existing conversation.

```http
POST /api/v1/messaging/messages
```

<ParamField body="conversation_id" type="integer" required>
  Target conversation ID.
</ParamField>
<ParamField body="message_text" type="string" required>
  Message content. Max 2,000 characters.
</ParamField>

**Response (201):**

```json
{
  "success": true,
  "data": {
    "id": 101,
    "conversation_id": 5,
    "message_text": "Sounds great, let's do it!",
    "user": { "id": 1, "name": "Producer A" },
    "created_at": "2025-01-15T14:31:00Z"
  }
}
```

## Read Status

### Mark Conversation as Read

Mark all messages in a conversation as read for the authenticated user.

```http
POST /api/v1/messaging/conversations/{conversationId}/read
```

### Mark Single Message as Read

Mark an individual message as read. Used for granular read receipts.

```http
POST /api/v1/messaging/messages/{messageId}/read
```

### Mark Conversation as Unread

Mark a conversation as unread (useful for reminders).

```http
POST /api/v1/messaging/conversations/{conversationId}/unread
```

### Get Unread Count

Get the total unread message count across all conversations.

```http
GET /api/v1/messaging/unread-count
```

**Response:**

```json
{
  "success": true,
  "data": {
    "unread_count": 5
  }
}
```

## Typing Indicators

### Set Typing Status

Notify participants that the authenticated user is typing.

```http
POST /api/v1/messaging/conversations/{conversationId}/typing
```

### Get Typing Status

Check who is currently typing in a conversation.

```http
GET /api/v1/messaging/conversations/{conversationId}/typing
```

<Note>
  Typing indicators are delivered in real-time. The REST endpoints provide fallback support.
</Note>

## User Discovery

### Search Users

Search for users to start a conversation with.

```http
GET /api/v1/messaging/search-users
```

### Get Followed Users

Get the authenticated user's followed users for quick messaging.

```http
GET /api/v1/messaging/followed-users
```

## Integration Example

```javascript
// Start a conversation and send a message
async function startConversation(userId, message) {
  const response = await fetch('https://open.beatpass.ca/api/v1/messaging/conversations/start', {
    method: 'POST',
    headers: {
      'Accept': 'application/json',
      'Content-Type': 'application/json',
      'Authorization': 'Bearer YOUR_TOKEN_HERE'
    },
    body: JSON.stringify({
      user_id: userId,
      message_text: message
    })
  });

  return response.json();
}
```

## Validation Rules

| Field | Rule |
|-------|------|
| `message_text` | Required, string, max 2,000 characters |
| `user_id` | Must exist in users table |
| `user_ids` | Array, min 2 participants for groups |
| `title` | Optional, max 255 characters |
