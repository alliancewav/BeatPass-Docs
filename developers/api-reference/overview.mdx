## OpenAPI Explorer

The **Endpoint Explorer** in the sidebar provides an interactive reference for a selection of these operations. Read the endpoint guide for workflow details and recovery steps.

<Steps>
  <Step title="Choose the operation">
    Check its HTTP method, path, authentication, parameters, and response type. Browser downloads, JSON responses, and CSV/PDF exports have different handling requirements.
  </Step>
  <Step title="Authorize protected requests">
    Use an approved developer token from **Account Settings → Developers**. Enter it in the explorer's **Authorization** field without adding a second `Bearer` prefix.
  </Step>
  <Step title="Check the destination before sending">
    **Try It** sends a real request to the configured server. The public host is production and there is no public sandbox. Use approved reads; arrange a separately authorized isolated environment for write and payment testing.
  </Step>
  <Step title="Handle the result">
    Inspect the HTTP status and endpoint-specific body. Do not infer payment completion, license validity, or file download completion from a successful request alone.
  </Step>
</Steps>

## Authentication & Access Tiers

Documented public reads can return public data without a token. Protected operations require valid authentication and the relevant account and resource permissions. A token does not authorize access to another account's private data.

[Authentication](/developers/auth) explains token creation, expiry, and `401`/`403` recovery.

### Public Request

```bash
curl "https://api.example.com/api/v1/tracks" \
  -H "Accept: application/json"
```

### Authenticated Request

```javascript
const response = await fetch('https://api.example.com/api/v1/tracks/900000007', {
  headers: {
    Accept: 'application/json',
    Authorization: 'Bearer YOUR_TOKEN_HERE'
  }
});
if (!response.ok) throw new Error(`Request failed: ${response.status}`);
const data = await response.json();
// Read the wrapper and fields documented for this operation.
```
