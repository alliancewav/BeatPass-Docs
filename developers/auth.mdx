Use a personal access token for an approved BeatPass integration. Your token identifies your account. Follow each documented operation's authentication, eligibility and resource-access requirements.

<ApiInviteOnly />

## Requesting API Access

<Steps>
  <Step title="Describe your integration">
    Email [contact@beatpass.ca](mailto:contact@beatpass.ca) with your use case, organization, and expected request volume. Access is reviewed individually.
  </Step>
  <Step title="Create a token after approval">
    Open **Account Settings → Developers**, select **Create token**, enter a **Token name**, then select **Create**. Select **Copy** before closing with **Done**. The full token is shown only once.
  </Step>
  <Step title="Keep the token on your server">
    Store it in your application's secret storage. Send it in the `Authorization` header of approved protected requests.

    <BearerAuthExample />
  </Step>
</Steps>

## Authentication Method

| Property | Contract |
| --- | --- |
| Header | `Authorization: Bearer {token}` |
| Expiration | 90 days from creation |
| Revocation | **Delete** the token in **Account Settings → Developers** |
| Permissions | API approval and the endpoint's account and resource rules still apply |

Create a replacement before a token expires, update your integration, and delete the old token once the replacement works. Deleting a token does not delete your account.

<Warning>
  Treat the token like a password. Keep it out of browser code, URLs, analytics, logs, screenshots, support messages, and version control. If it is exposed, delete it and create a replacement.
</Warning>

## API Access Tiers

| Request | Expected access |
| --- | --- |
| Documented public read without a token | Public fields for that endpoint |
| Approved token with permission for the operation | The fields and actions allowed by that endpoint |
| Protected request without valid authentication | `401` |
| Authenticated request without the required access | `403` |

Response fields differ between endpoints. Do not assume that a token unlocks every field, grants ownership, or makes a protected operation public when authentication fails. Use the endpoint's response contract.

## Authentication Errors

<AccordionGroup>
  <Accordion title="401 — check the token" icon="key">
    Check that the token is present, complete, and unexpired. Generate a replacement if needed. Avoid repeatedly retrying the same rejected credentials.

    ```json
    { "message": "Unauthenticated." }
    ```
  </Accordion>
  <Accordion title="403 — check permission" icon="lock">
    Confirm your account has API approval, access to the feature, and permission for the requested resource. A new token does not change account eligibility. Contact BeatPass when the account should have access.
  </Accordion>
</AccordionGroup>

## Security

Use HTTPS and stay within your approved integration scope and the [Terms of Service](https://open.beatpass.ca/pages/terms-of-service). Request only data your integration needs. Remove private account data from diagnostic reports before sharing them.
