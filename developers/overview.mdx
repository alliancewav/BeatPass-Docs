## Response Format

### Success Response

Response envelopes vary by endpoint. Track listing returns `status` and `pagination`, while dashboard statistics return `success` and `data`. Dashboard fields such as `total_tracks` and `total_plays` are inside `data`. Use the response contract for the specific endpoint.

### Error Response

Illustrative validation error only. Endpoints use different envelopes; see the [Error Catalog](/developers/error-catalog).

```json
{
  "message": "Error description",
  "errors": {
    "field": ["Validation error"]
  }
}
```

### Pagination

Pagination is endpoint-specific. `GET /tracks` wraps its page in `pagination` alongside `status: "success"`. It uses the following page-number forms; other endpoints can use different field names or cursor/offset pagination.

Length-aware pages include `total`, `last_page`, and numeric `next_page`/`prev_page`. Simple pages omit totals and last-page counts and instead include `next_page_url`/`prev_page_url`. Use `paginate=simple` to request simple pagination, and handle the form returned by the endpoint.

For track listing, `per_page` defaults to 15 and is capped at 500. `from` and `to` are 1-based positions for the displayed items and are null on an empty page. A length-aware `last_page` is at least 1, including when `total` is 0. Retain the request's page size and filters when moving between pages.

Synthetic, nonfunctional documentation fixtures only. Names, identifiers, URLs and counts are invented, not copied from accounts or a live response. Numeric IDs can coincide with real records; never send these fixtures to a live API.

        "updated_at": "2026-01-01T00:00:00.000000Z",
        "model_type": "track",
        "duration_text": "3:00",
        "views": 0,
        "plays": 0,
        "artists": [],
        "genres": []
      }
    ],

## Authentication & Data Access

Documented public reads return public endpoint data without a token. Protected operations require an approved Bearer token and the relevant account and resource permissions. A missing or rejected token does not turn a protected request into a public read.

Response fields are endpoint-specific. See [Authentication](/developers/auth) for token creation, expiry, and error handling.

---

## Endpoint Categories

The API provides read access to public content (tracks, artists, albums, genres, search) and authenticated access to user-specific features (library, playlists, messaging, purchases, analytics).

Authentication and permissions vary by endpoint. Use producer and insights endpoints only for resources you are authorized to manage. A valid token alone does not establish ownership or authorize access to another producer's data.

See the [API Reference](/developers/api-reference/overview) for the full endpoint listing.
