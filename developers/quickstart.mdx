## Authentication

Approved external integrations use **Bearer token authentication** for protected endpoints. Some public reads also work without a token:

<BearerAuthExample />

| Detail | Value |
|--------|-------|
| **Access** | Invite-only, granted by BeatPass team |
| **Token expiration** | 90 days from creation |
| **Data access** | Endpoint-specific permissions apply |

<Info>
  **Response fields vary by endpoint.** A token permits only the fields and operations allowed for your account. Use the endpoint-specific response contract.
</Info>

### Development Best Practices

Use synthetic fixtures while developing locally. A sample account, placeholder ID, or small payment does not create a sandbox.

- Confirm the approved host and read endpoints before making requests.
- Run write and payment tests only in a separately authorized, isolated test environment.
- Do not create uploads, messages, purchases, or cleanup jobs on the live platform as a development exercise.
- Keep tokens and personal data out of logs and shared examples.

## Using Placeholder IDs

When developing or documenting:

### Recommended Placeholders

| Entity | Placeholder Format | Example |
|--------|-------------------|---------|
| Track ID | `{track_id}` | `/tracks/{track_id}` |
| User ID | `{user_id}` | `/users/{user_id}` |
| Artist ID | `{artist_id}` | `/artists/{artist_id}` |
| Album ID | `{album_id}` | `/albums/{album_id}` |

### In Code Examples

<SyntheticFixtures />

```javascript
const trackId = '{track_id}'; // Replace only in an authorized environment.
```

### In Documentation

```http
GET /api/v1/tracks/{track_id}
```

## Restricted Access

<Warning>
  **Undocumented endpoints are off-limits.** API approval does not authorize internal routes or another account's private data. API use remains subject to the [Terms of Service](https://open.beatpass.ca/pages/terms-of-service).
</Warning>

If you encounter a 403 Forbidden response, the endpoint requires permissions your account does not have. Contact support if you believe this is an error.

---

## Safe API Usage

### Do

- Use documented endpoints only
- Respect rate limits
- Handle errors gracefully
- Keep development fixtures in an authorized isolated environment
- Log responsibly (no sensitive data)

### Don't

- Scrape or crawl the platform
- Hammer endpoints with excessive requests
- Store user credentials
- Bypass authentication
- Share authentication credentials

## Error Handling

### Example Validation Error

Error bodies vary by endpoint. This is one validation-error shape; do not assume every error has an `errors` object.

```json
{
  "message": "Human-readable error",
  "errors": {
    "field": ["Validation error message"]
  }
}
```

## Getting Started Checklist

<Steps>
  <Step title="Request API Access">
    Contact [**support@beatpass.ca**](mailto:support@beatpass.ca) with your use case and organization details.
  </Step>
  
  <Step title="Generate Token">
    Once approved, go to **Account Settings → Developers** to create your token.
  </Step>
  
  <Step title="Review Documentation">
    - Read the [API Overview](/developers/overview)
    - Understand [Authentication](/developers/auth)
    - Note [Rate Limits](/developers/rate-limits)
  </Step>
  
  <Step title="Start Building">
    - Begin with approved read-only endpoints (tracks, artists, search)
    - Use placeholder IDs in development
    - Monitor rate limit headers
    - Handle errors gracefully
  </Step>
</Steps>
