This is an archived release note for the version and date shown. For current instructions, start in [BeatPass Help](/help). Use the [current Beat Requests guides](/help/beat-requests) for sending beats, limits, and token-refund conditions.

## Summary

This release improved beat-request reliability, token handling and the option to send a beat from your existing catalog.

## What's New

- **Reliable Requests**: Request records and token updates are handled together more consistently.
- **Correct Refund Handling**: Request-deletion refunds are applied to the appropriate request owner.
- **Duplicate Prevention**: Added strict checks to prevent accidental duplicate submissions of the same track.
- **Existing Track Selection**: Producers can now select from their existing catalog when fulfilling requests, instead of re-uploading.
- **Improved Feedback**: Clearer error messages (e.g., "Already submitted") instead of generic server errors.

## Why It Matters

More reliable request records, clearer submission feedback and existing-beat selection make it easier to respond to a brief without repeating work.

## How to Use

No action is required from users. The system works seamlessly with the existing interface.
- **Producers**: When fulfilling a request, look for the new "Select Existing Track" option.
- **Request Owners**: The release corrected refund ownership when requests were deleted. See the [current refund conditions](/help/beat-requests/understanding-tokens) before deleting a request.
