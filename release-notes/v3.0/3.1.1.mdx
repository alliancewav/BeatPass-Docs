# Producer Access Request Guard & Appeal Flow

## Summary

This release closes a critical producer onboarding gap by preventing duplicate Backstage submissions and introducing a clear appeal path when access has been revoked. It also expands technical API documentation for producer requests and refreshes Audio Recon documentation to match current platform behavior.

---

## What's New

### Backstage Submission Guard

- **Duplicate pending requests blocked** — You can no longer create a second request while one is already under review
- **Revoked re-submission blocked** — If your producer access was revoked, you can't open a new request flow
- **Consistent across request types** — The guard applies to becoming an artist, verifying an artist, and claiming an artist

### Revoked Appeal Experience

- **Clear guidance when access is paused** — The request screen now shows an explicit appeal message and a clear **Contact Support** action
- **Standard appeal path** — You're directed to the contact page for review and possible reinstatement
- **Deep-link protection** — Direct navigation to request forms is blocked when you're not currently eligible

### Producer Access Reviews

- **You're always notified** — If your producer access is paused, you receive a dedicated email and in-app notification explaining what changed
- **A path back** — Paused access can be reinstated when appropriate after a review

### Documentation & Developer Coverage

- **Help docs updated** — Producer Program application guidance now includes pending/revoked submission rules and appeal behavior
- **Developer docs expanded** — Content API and Error Catalog now document Backstage submission status, create conflict behavior, and revoke flow
- **Audio Recon docs refreshed** — Clarified current scan cadence and high-confidence match visibility details

---

## Why It Matters

- **Prevents request spam and duplicate records** in producer onboarding workflows
- **Gives revoked users a clear, controlled appeal channel** instead of opening new requests
- **Makes the request flow more predictable** with clear eligibility checks
- **Keeps docs accurate** for both end users and API consumers
